### CLASSIFICATION: CLASS III CRITICAL INFRASTRUCTURE // REAL-TIME DECISION ONTOLOGY // V2.0

This document defines the semantic ontology extensions required to model programmatic and human-in-the-loop decisions within Salience Atlas V2. By formalizing decisions, recommendations, and evidence into first-class graph elements (vertices and edges), the platform eliminates black-box AI logic, guaranteeing that every automated recommendation can be legally and programmatically audited.

## 2. DYNAMIC DECISION CORE VERTICES

The decision-making fabric of Salience Atlas V2 utilizes ten (10) highly structured vertices representing the complete lineage of an active decision space:

1.  **Decision**: The master container representing a high-integrity commitment, choice, or operational directive (e.g., "Award 400kV Transformer Contract to ABB Kenya").
2.  **Recommendation**: An advisory option generated by an autonomous agent pool or optimization routine (e.g., "Tender-Agent recommends alternative Supplier B due to Siemens logistics bottleneck").
3.  **Alternative**: A viable decision choice rejected during the evaluation process. Maintains cost-benefit trade-offs, risk deltas, and justification metrics.
4.  **Evidence**: Verified operational facts, ledger events, or statutory rules backing a recommendation or decision (e.g., "Supplier B has 94% on-time logistics scoring under East Africa corridor trials").
5.  **Hypothesis**: A proposed causal relationship tested in the background before formulating recommendations (e.g., "If raw copper prices rise 14%, Contractor C will default within 90 days").
6.  **Simulation**: A stochastic Monte Carlo execution run in a sandboxed thread pool showing systemic impacts of a simulated scenario.
7.  **Scenario**: The container of variables representing target disruption parameters (e.g., "Simulated Red Sea shipping lockout for 45 calendar days").
8.  **Constraint**: Rigid physical, legal, or financial limits bounding viable options (e.g., "PPADA Part XII local sourcing threshold: material local content must exceed 40%").
9.  **Approval**: The cryptographic multi-signature authorization gateway tracking human-in-the-loop sign-offs and legal delegations of power.
10. **Outcome**: The post-execution metrics capturing the actual real-world impact of the decision, providing data loops for cognitive learning.

## 3. SEMANTIC DECISION EDGES (RELATIONSHIPS)

Decisions paths rely on ten (10) highly specialized relationship edges:

-   `SUPPORTED_BY [Recommendation / Decision → Evidence]`: Traces choices directly to factual, immutable log entries.
-   `CONSTRAINED_BY [Recommendation / Decision → Constraint]`: Ties options to legal (PPADA) or physical boundaries.
-   `APPROVED_BY [Decision → Approval]`: Cryptographic signing trace mapping human owners to finalized choices.
-   `REJECTED_BY [Alternative → Decision]`: Tracks which alternative paths were bypassed during human selection.
-   `GENERATED_FROM [Recommendation → Prediction / Scenario]`: Records the systemic origin of an option.
-   `SIMULATED_BY [Decision / Scenario → Simulation]`: Backlinks options to sandboxed stress-test runs.
-   `RESULTED_IN [Decision → Outcome]`: Closes the cognitive feedback loop by tying selections to actual operational outcomes.
-   `CONFLICTS_WITH [Recommendation → Recommendation]`: Flags operational incompatibilities between two distinct agents.
-   `SUPERSEDES [Decision → Decision]`: Manages temporal overrides where emergency decisions replace baseline choices.
-   `REPRESENTS [Evidence → Contract / Supplier / Inventory]`: Hooks factual vertices directly into operational Digital Twins.

## 4. SCHEMA AND LINEAGE VALIDATION SPECIFICATIONS

All decisions are bound by a rigid, non-repudiation framework. Properties carried by a `Decision` block are crypotgraphically locked upon transition:

```typescript
interface DecisionVertex extends BaseVertex {
  contextId: string;              // Links to target Digital Twin (e.g., Tender Twin URN)
  objective: string;              // Human-readable statement of purpose
  evidenceHashes: string[];       // SHA-256 integrity checks of supporting Evidence blocks
  reasoningTraces: string[];       // Sequence paths from the Causal Reasoning Engine
  alternatives: string[];         // Identifiers of evaluated but rejected alternatives
  riskAssessmentHash: string;     // Reference to Monte Carlo simulation values
  complianceChecked: boolean;     // Enforces automated regulatory rules checks
  approvalChainId: string;        // Active tracking ID on the multi-signature workflow
  outcomeState: 'PENDING' | 'EXECUTING' | 'SUCCESSFUL' | 'REGULATORY_REJECTED' | 'OPERATIONAL_FAILURE';
  executionTransactionId?: string;// Reference link to the immutable Ledger block
}
```

This strict architectural layout guarantees that Salience Atlas V2 remains impervious to cognitive hallucination. No agent may recommend an action without structuring it within this trace schema, ensuring absolute traceability under critical procurement reviews.
