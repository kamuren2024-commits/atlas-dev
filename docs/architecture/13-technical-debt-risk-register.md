## 3. Deep-Dive Remediation Actions

### Remediation Plan for RSK-01 (Prisma / Database):
1. Create a native SQLite table `registered_agents` in `backend/database/db-core.ts`.
2. Refactor `backend/agents/registry.ts` to perform queries against `DatabaseCore.getInstance()` instead of `this.prisma.agent`.
3. Provide a valid `prisma/schema.prisma` matching the 93 tables in `data/salience_atlas.db` to restore the Prisma generation pipeline.

### Remediation Plan for RSK-02 (AI Federation):
1. Mount `POST /api/ai/chat` and `GET /api/ai/status` directly in `server.ts`.
2. Wire these routes to `AIFederationService.getInstance().chat()`, supporting both local Ollama and `@google/genai` (Gemini 2.5).
3. Log all chat transactions to SQLite table `ai_execution_logs`.

### Remediation Plan for RSK-03 (Security):
1. Move user credentials to SQLite table `users` with bcrypt-hashed passwords.
2. Generate dynamic cryptographically secure JWT secrets if unset in production, and enforce authorization checks across all sensitive API routes.

### Remediation Plan for RSK-04 & RSK-05 (Durability & Testing):
1. Add append-only table `event_ledger` in SQLite for the Event Fabric.
2. Fix broken relative imports in `backend/tests/event-fabric.*.test.ts`.
3. Add a unified `"test"` command to `package.json` utilizing `node:test` via `tsx --test`.
